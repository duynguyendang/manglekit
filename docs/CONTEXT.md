## 1. Architecture Overview

Manglekit is a Go framework for building neuro-symbolic AI applications. It combines neural components (LLMs, Embedders) with a symbolic layer (Mangle Datalog engine) to create verifiable and controllable AI workflows. The architecture is modular, with components registered in a central `Registry` and wired together by a `Builder`.

### 1.1. Configuration and Build Flow

The SDK's initialization process is designed to be clear, testable, and type-safe, following a strict one-way dependency flow.

```mermaid
graph TD
    A[YAML / Env Vars] -->|Load| B(config.LoadFromYAML / config.LoadFromEnv);
    B --> C{config.Config Struct};
    C -->|Normalize & Validate| D(Validated Config);
    D -->|NewBuilderFromConfig| E[Builder];
    E -->|b.WithLLM(opts)| F[LLM Component];
    E -->|b.WithRetriever(opts)| G[Retriever Component];
    E -->|...| H[Other Components];
    F & G & H -->|b.Build()| I(Orchestrator);
```

**Key Principles:**

1.  **Decoupled Config:** The `config` package is a data-only package. It defines the configuration schema, loads it from external sources (YAML, env vars), applies defaults (`Normalize`), and validates the data (`Validate`). It has **zero knowledge** of the rest of the application.
2.  **Single Wiring Entrypoint:** `manglekit.NewBuilderFromConfig` is the sole function responsible for translating a validated `config.Config` object into a fully configured `Builder`. It maps config sections to the builder's fluent `With...` methods.
3.  **Programmatic Wiring:** The `Builder` provides a fluent API (`WithLLM`, `WithRetriever`, etc.) for programmatic, type-safe component assembly. This is the underlying mechanism used by `NewBuilderFromConfig`.

This clean separation of concerns (loading vs. wiring) is a core architectural principle.

## 2. Core Components & Status

| Component               | Status | Path                               | Description                                                                                             |
| ----------------------- | ------ | ---------------------------------- | ------------------------------------------------------------------------------------------------------- |
| **Configuration**       | ✅      | `config/`                          | Defines, loads, and validates the application configuration.                                            |
| **Builder**             | ✅      | `builder.go`, `from_config.go`     | Wires components together programmatically. The central point for dependency injection.                 |
| **Registry**            | ✅      | `registry.go`                      | A central store for registering and discovering component factories (LLMs, Retrievers, etc.).           |
| **Sandwich Orchestrator** | ✅      | `pipeline/sandwich.go`             | A simple, fixed-sequence RAG pipeline (`Rules -> Retrieve -> Rerank -> LLM`).                           |
| **Declarative Orchestrator**| ⚠️      | `pipeline/declarative/`            | A more powerful, Datalog-driven orchestrator. Currently disabled/stubbed.                               |
| **State Management**    | ✅      | `state/`, `internal/statehelper`   | Manages conversational state, allowing for stateful workflows on a stateless architecture.              |
